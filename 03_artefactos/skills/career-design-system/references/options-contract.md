# Contrato de alternativas

## Entrada

Design brief aprobado, contenido exclusivamente sintético y design system
candidato. [PEDAGOGIA] Mantener contenido idéntico aísla la variable visual y
hace la comparación comprensible. [INFERENCIA]

## Salida exacta

- `blueprint-executive.md` + HTML autocontenido.
- `neo-swiss-editorial.md` + HTML autocontenido.
- Comparador desktop/móvil.
- Manifest con hashes y estado `DESIGN_OPTIONS_READY`.

Ambas cubren hero, experiencia, resultados, competencias, navegación, navy/light,
impresión, responsive, `<details>` y `<dialog>`. No usan PII, claims reales,
dependencias remotas o keywords ocultas.

## Decisión

El aprobador elige primary y secondary. La decisión incluye hashes de las opciones,
timestamp, scope y exclusiones. No se interpreta silencio o navegación como voto.
