# Trainer OS routing contract

[METODOLOGIA] Keep the router under 300 whitespace tokens. Accept a minimum brief containing
topic and audience; label every inferred problem, outcome, duration, source or language as an
editable assumption. Ask at most two questions only when a missing answer changes the route.

Return exactly two directions. Describe the distinct narrative, learning progression and main
trade-off of each. Do not silently blend them. Selection freezes the route spec and design lock;
later source, curriculum or design changes invalidate downstream artifacts and approvals.

[PEDAGOGIA] Derive practice, evidence and transfer from one route specification. A standard
shape is a default, not permission to add sections without utility.

Route only declared artifacts. Read each capability skill on demand. Compile with the shared
Trainer OS runtime and preserve `INTAKE -> CONTEXT_READY -> SPEC_READY -> DESIGN_LOCKED ->
COMPILED -> VERIFIED -> HUMAN_REVIEW -> RENDERED_DRAFT`.

[INFERENCIA] Fewer prompts come primarily from reusable contracts and deterministic compilers,
not from omitting decisions. Keep the nominal interaction to four prompts, with a hard range of
three to five.

[SUPUESTO] Runtime readiness remains blocked until independent evaluation. Do not publish,
activate network or connectors, persist participant content, or store real operational receipts
in Frames.

[NEUROCIENCIA] Reject unsupported cognitive or neuroscience claims.
