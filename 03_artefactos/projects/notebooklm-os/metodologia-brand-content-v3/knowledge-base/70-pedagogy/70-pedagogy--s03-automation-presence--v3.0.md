# Abstract

S03 designs useful automatic behavior while preserving human presence for judgment, trust, creativity, ambiguity, and irreversible decisions. SPEC makes Situation, Request, Execution, and Criteria observable. [METODOLOGIA][source_ref:NFC-DRV-S03]

</abstract>

<knowledge>

# Prerequisites and concepts

Prerequisite: a recurring decision or task. Concepts: trigger-response-consequence; useful and harmful automatisms; presence signals; SPEC; priming; staged execution; verification; crystallization into a reusable asset.

# Sequence

Map a working day. Classify automatic responses. Identify risk and intervention signals. Rewrite a vague request as SPEC. Execute understand → specify → plan → produce → challenge → verify → crystallize. Extract reusable context and procedure.

# Misconceptions

All repetition should be automated; criteria belong at the end; a prompt library is valuable by volume; a self-improvement command replaces review; oral study references are evidence.

# Practice and transfer

Build and execute one SPEC plus a human-intervention checklist. Transfer by choosing an apparently automatable task that must pause under one realistic condition. [PEDAGOGIA]

</knowledge>
<evidence>

# Evidence

Expected evidence: SPEC, output, verification, intervention trigger, retained human decision, and reusable successor asset.

</evidence>
<decisions>

# Decisions

Automate only after failure and approval conditions are explicit. Preserve deliberate friction where it improves decision quality.

</decisions>
<assumptions>

# Assumptions

[SUPUESTO] The selected task can be tested without causing an irreversible effect.

</assumptions>
<limits>

# Limits

SPEC improves clarity but cannot guarantee correctness. Presence is an operating concept here, not a clinical or neuroscientific claim.

</limits>
<edge_cases>

# Edge cases

If execution is irreversible, simulate. If criteria conflict, resolve precedence before production. If the learner lacks domain knowledge, use critique and sources before synthesis.

</edge_cases>
<acceptance>

# Acceptance

The learner justifies what is automated and preserved, produces an observable SPEC, verifies the result, and defines a stop/escalation signal. [PEDAGOGIA]

</acceptance>
