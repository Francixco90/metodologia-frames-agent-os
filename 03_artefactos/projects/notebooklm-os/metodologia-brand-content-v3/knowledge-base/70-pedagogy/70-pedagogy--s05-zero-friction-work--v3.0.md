# Abstract

S05 removes avoidable operational friction while preserving the deliberate friction that protects learning, quality, privacy, and responsibility. A reusable SOP makes trigger, inputs, steps, owner, exceptions, and acceptance explicit. [METODOLOGIA][source_ref:NFC-DRV-S05]

</abstract>

# Routing

Use for S05, SOPs, and reusable skills. External tool permissions and memory route to Control/Operations.

</routing>
<knowledge>

# Prerequisites and concepts

Prerequisite: a repeated task and one recent failure. Concepts: harmful, protective, and learning friction; work in progress; backward design from acceptance; SOP; human-in-the-loop; skill versus agent instruction; information architecture and retrieval.

# Sequence

Inventory recurring irritants. Classify each friction. Select one task and trace it backward from acceptance. Document trigger, inputs, steps, owner, decision points, exceptions, and evidence. Execute with another person or tool. Record failure and create a successor. Test retrieval and portability.

# Misconceptions

All friction is waste; a skill can compensate for an undefined procedure; more tools improve flow; memory/connectors are harmless; initial speed proves repeatability.

# Practice and transfer

Build and run one SOP. Transfer it to a second operator or context and identify which context must remain external rather than embedded. [PEDAGOGIA]

</knowledge>
<evidence>

# Evidence

Expected evidence: before-flow, friction classification, versioned SOP, execution log, exception handling, and successor changes.

</evidence>
<decisions>

# Decisions

Optimize for repeatability before speed. Keep privacy, approval, and quality checks even when they feel slower.

</decisions>
<assumptions>

# Assumptions

[SUPUESTO] The task repeats often enough to justify documentation.

</assumptions>
<limits>

# Limits

Do not universalize time-savings or license estimates. A documented procedure can still encode a flawed process.

</limits>
<edge_cases>

# Edge cases

For rare high-risk tasks, use a checklist rather than automation. If portability exposes secrets, parameterize them and keep secret storage outside the skill.

</edge_cases>
<acceptance>

# Acceptance

The learner distinguishes friction classes and delivers a procedure another actor can execute, verify, stop, and improve without hidden knowledge or removed safeguards. [PEDAGOGIA]

</acceptance>
