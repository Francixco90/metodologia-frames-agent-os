# Abstract

MetodologIA content turns grounded information into an experience that helps a defined audience understand, remember, decide, or act. Editorial design organizes meaning and attention; it does not decorate unsupported claims. [METODOLOGIA][source_ref:LEGACY-KB-12-CONTENT-V1]

# Editorial compiler

1. State the audience, decision, or learning outcome.
2. Write the conclusion in one sentence.
3. Select up to three non-overlapping supports and bind strong claims to evidence.
4. Declare uncertainty, exclusions, and one next movement.
5. Choose a format because its interaction model fits the outcome.
6. Define one functional visual relation—sequence, comparison, hierarchy, flow, system, or magnitude.
7. Compile a format-specific brief; generate; download; read back; verify; create a successor when correction is needed.

**Engineering of Wonder** combines relevance, clarity, functional aesthetics, and human judgment. It is an editorial standard, not a measurable guarantee of surprise or impact. [METODOLOGIA][source_ref:NFC-DRV-T22]

# Format contracts

- **LinkedIn:** recognizable tension → thesis → evidence/example → limit → one CTA.
- **One-pager:** audience and decision → method → proof → constraints → next step.
- **Deck:** narrative arc; one dominant claim per slide; sources in notes; editable successor after Studio raw.
- **Masterclass:** current state → tension → reframe → framework → application → practice → acceptance.
- **Playbook:** problem → principle → diagnosis → procedure → example → failure modes → action.
- **Audio/video:** script for listening or scenes, not prose read aloud.
- **Infographic/mind map/data table:** one explicit relation; labels, units, and sources.
- **Flashcards/quiz:** retrieval and diagnosis; do not use trick questions or ambiguous distractors.
- **Report:** traceability and decision usefulness over visual novelty.

</knowledge>
<evidence>

# Evidence

Format patterns are editorial methodology derived from MetodologIA materials. Claims inside an artifact inherit the authority and validity of their cited sources, not of this canon. [METODOLOGIA][source_ref:LEGACY-KB-12-CONTENT-V1]

</evidence>
<decisions>

# Decisions

- Use prose when a visual would not improve understanding.
- Use one format-specific brief; never reuse a generic prompt across media.
- Treat Studio output as raw until type, language, evidence, bytes, accessibility, and visual quality are read back.

</decisions>
<assumptions>

# Assumptions

[SUPUESTO] The brief identifies a real audience and an observable outcome. [SUPUESTO] Source selection and asset approval are handled by their controlling documents.

</assumptions>
<limits>

# Limits

This canon does not authorize publication, imply ROI, or make rasterized PDFs editable or accessible. A visually attractive artifact can still fail evidence, rights, or usability.

</limits>
<edge_cases>

# Edge cases

- If audience and decision diverge, create separate artifacts.
- If the evidence is thin, narrow the thesis or present a question—not a stronger claim.
- If a requested format conflicts with accessibility or editability, disclose the trade-off and provide an accessible companion.
- If a visual metaphor distorts the evidence, remove it.

</edge_cases>
<acceptance>

# Acceptance

The piece has one repeatable thesis, explicit sources for strong claims, channel-native structure, correct brand identity, approved assets, functional visual logic, accessible reading order, and one proportionate action. Internal prompts, gates, IDs, and reasoning are absent from the user-facing surface.

</acceptance>
