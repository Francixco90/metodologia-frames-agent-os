# Abstract

Onboarding establishes how to participate in the Empowerment Program: use sources and AI as bounded support, bring real practice cases, preserve human accompaniment, and distinguish generated guidance from verified learning and approval. [METODOLOGIA][source_ref:LEGACY-KB-27-ONBOARDING-V1-1]

<knowledge>

# Orientation contract

The participant brings a concrete capability or work tension, selects the relevant session and sources, practices in a safe context, captures evidence and questions, seeks facilitator feedback, and creates a successor practice. The notebook supports retrieval and source-grounded exploration; it does not replace facilitation, domain expertise, consent, or final judgment. [METODOLOGIA]

Recommended orientation: explain the program's method-first premise; show how to ask scoped questions with selected sources; model evidence labels and gaps; demonstrate one practice-feedback loop; state privacy and sharing boundaries; clarify how technical verification and human approval differ.

</knowledge>
<evidence>

# Evidence

This reference consolidates historical onboarding material. It does not establish that onboarding is identical to S02 or that participation causes business or personal outcomes.

</evidence>
<decisions>

# Decisions

Keep onboarding as an active reference, not competing curriculum canon. Use one current orientation artifact and preserve historical editions separately.

</decisions>
<assumptions>

# Assumptions

[SUPUESTO] A facilitator or program owner remains available for material questions and approval.

</assumptions>
<limits>

# Limits

Do not promise transformation, certification, income, wellbeing, or autonomy from attendance. Do not import participant PII into the brand notebook.

</limits>
<edge_cases>

# Edge cases

For self-directed participants, define an explicit reviewer and feedback cadence. For confidential cases, abstract the pattern or use a synthetic fixture. If current program operations differ, update onboarding without changing curriculum authority.

</edge_cases>
<acceptance>

# Acceptance

The participant can state the program purpose, source and privacy rules, one practice-feedback cycle, the role of human review, and the next concrete learning action.

</acceptance>
