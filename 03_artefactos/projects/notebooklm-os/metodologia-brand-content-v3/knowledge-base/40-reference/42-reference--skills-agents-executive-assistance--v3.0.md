# Abstract

A skill packages a reusable procedure, required knowledge, constraints, resources, and acceptance. An executive assistant becomes operational only when registry, policy, memory, tools, execution, and governance are explicit. [INFERENCIA][source_ref:LEGACY-KB-42-SKILLS-AGENTS-V1]

# Capability patterns

A skill description should support semantic routing; its primary instruction governs procedure; supporting resources load only when needed. A digital Chief of Staff follows intake → current context and permissions → prioritization and plan → bounded execution → independent verification → receipt/readback → next gate. [METODOLOGIA]

Autonomy is asymmetric: reversible, low-risk internal work can proceed under policy; money, reputation, people, privacy, external communication, irreversible changes, and strategic commitments escalate to a human.

</knowledge>
<evidence>

# Evidence

Provider-specific file conventions, tool compatibility, and protocol support are time-sensitive and require official documentation at use time.

</evidence>
<decisions>

# Decisions

Treat imported blueprints as examples, not mandatory architectures. A declared skill is planned; only material evidence proves execution.

</decisions>
<assumptions>

# Assumptions

[SUPUESTO] The host can enforce or at least observe permissions and effects.

</assumptions>
<limits>

# Limits

No claim of autonomy, ROI, provider superiority, or readiness follows from a scaffold or persona.

</limits>
<edge_cases>

# Edge cases

If a low-risk task exposes sensitive data, treat it as high risk. If a skill cannot state acceptance, keep it experimental. If a connector cannot read back, do not claim delivery.

</edge_cases>
<acceptance>

# Acceptance

The capability has clear routing, inputs, procedure, limits, owner, tests, evidence of execution, and an escalation path proportional to effects.

</acceptance>
