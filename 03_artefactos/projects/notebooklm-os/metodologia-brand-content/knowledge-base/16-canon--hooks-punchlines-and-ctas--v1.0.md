# Hooks, punchlines y llamadas a la acción

Versión: `v1.0`
Propietario: `MetodologIA`
Estado: `ACTIVE_CANON`

Este canon convierte atención en comprensión y acción sin clickbait. Un hook abre una tensión verdadera; una punchline condensa una idea demostrada; un CTA propone un solo movimiento. [METODOLOGIA]

## Hooks autorizados

Un hook debe ser compatible con la evidencia que aparecerá después. Elige una forma, no varias a la vez:

1. **Conclusión incómoda:** `Automatizar el caos solo acelera el caos.`
2. **Contraste:** `No necesitas más prompts. Necesitas mejores criterios.`
3. **Pregunta diagnóstica:** `¿Qué parte de este resultado todavía depende de tu memoria?`
4. **Síntoma reconocible:** `Tienes veinte respuestas y ninguna decisión.`
5. **Cambio de unidad:** `El activo no es el prompt: es el método que puedes volver a ejecutar.`
6. **Antes/después verificable:** `De pedir una respuesta a definir un acuerdo verificable.`
7. **Límite útil:** `La IA puede proponer; la aceptación sigue siendo humana.`

Plantilla: `[tensión real] + [consecuencia o giro]`. La siguiente línea debe explicar, demostrar o situar la tensión. [METODOLOGIA]

## Punchlines

La punchline no introduce una promesa nueva. Cierra o pivota una idea ya sustentada.

Patrones:

- **Regla de tres:** `Método primero. IA después. Criterio siempre.`
- **Reencuadre:** `No delegues el juicio; delega la mecánica.`
- **Causalidad acotada:** `Sin criterio, más velocidad produce más retrabajo.`
- **Propiedad:** `La capacidad es tuya cuando sobrevive a la herramienta.`
- **Decisión:** `Primero define qué debe ser verdad al final.`

Criterios: máximo 14 palabras cuando funcione como cierre visual; ritmo oral; una sola idea; ninguna cifra o garantía no sustentada. [METODOLOGIA]

## CTAs de un movimiento

El CTA debe indicar una acción concreta, proporcional y coherente con la etapa del lector.

| Intención   | CTA recomendado                                                              |
| ----------- | ---------------------------------------------------------------------------- |
| Reflexionar | `Identifica una decisión que hoy estás delegando sin criterio.`              |
| Practicar   | `Reescribe una instrucción con Situación, Pedido, Ejecución y Criterios.`    |
| Verificar   | `Selecciona una afirmación fuerte y vuelve a su fuente primaria.`            |
| Diseñar     | `Convierte este proceso repetido en un activo con entrada, salida y prueba.` |
| Conversar   | `Cuéntame qué parte del proceso todavía genera más fricción.`                |

Evita CTAs dobles, urgencia falsa, `comenta y comparte` por defecto, o llamados comerciales en piezas formativas salvo brief autorizado.

## Ensamble por canal

### LinkedIn

`Hook de una o dos líneas → situación reconocible → tesis → tres apoyos como máximo → límite → punchline → CTA`.

### Carrusel o deck corto

`Portada con tensión → costo → reencuadre → método → ejemplo → verificación → cierre`. Una idea por lámina y punchlines solo en puntos de giro.

### One-pager

`Decisión principal → para quién/para qué → método → evidencia → restricciones → siguiente paso`.

### Formación

`Pregunta o síntoma → explicación → ejemplo → práctica → criterio de aceptación → reflexión`.

## Antipatrones

- Pregunta que el cuerpo nunca responde.
- Punchline intercambiable con cualquier marca.
- Suspenso artificial: `Lo que pasó después te sorprenderá`.
- Enemigo inventado o vergüenza del lector.
- Promesa absoluta basada en una experiencia anecdótica.
- Cinco hooks seguidos antes de entregar valor.
- CTA que exige confianza o compromiso mayor que la evidencia disponible.

## Prueba rápida

Antes de aprobar un borrador:

1. cubre el nombre de la marca: ¿el hook sigue siendo específico al problema?;
2. señala la evidencia que satisface la tensión inicial;
3. lee la punchline en voz alta: ¿es clara sin explicación adicional?;
4. identifica el único verbo del CTA;
5. bloquea si alguna línea exagera el alcance de las fuentes.
